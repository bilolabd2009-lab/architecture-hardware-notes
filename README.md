# Конспект по дисциплине «Архитектура аппаратных средств»

## Тема: Как работает процессор и что такое машинная команда

---

## 1. Что такое процессор и из чего он состоит

**Процессор** — это главная микросхема компьютера, которая выполняет команды программы. Можно представить его как «мозг» ПК.

### Основные элементы процессора

| Элемент | Простыми словами |
|---|---|
| **Дешифратор команд** | «Переводчик»: получает код команды и объясняет устройству управления, что нужно сделать |
| **АЛУ** (арифметико-логическое устройство) | «Калькулятор»: выполняет сложение, вычитание, логические операции (И, ИЛИ, НЕ) |
| **Устройство управления (УУ)** | «Дирижёр»: руководит всеми блоками, говорит, когда что делать |
| **Регистры** | «Карманы» процессора: быстрая память внутри него для временного хранения чисел |
| **Транслятор адресов** | «Навигатор»: превращает адрес операнда в реальный адрес в памяти |
| **Шины** | «Дороги»: проводники, по которым передаются данные внутри процессора и наружу |

> **Важно:** В 1971 году появился первый микропроцессор Intel 4004. Он был такой же мощный, как огромный компьютер ENIAC, но стоил всего 200 долларов, содержал 2300 транзисторов и работал на частоте 108 кГц.

## 2. Операционные устройства

**Операционное устройство** — это то, что непосредственно выполняет операции над данными.

### Что умеют операционные устройства

- Целочисленная арифметика (сложение, вычитание целых чисел)
- Логические операции (И, ИЛИ, НЕ)
- Сдвиги (сдвиг битов влево/вправо)
- Десятичная арифметика
- Операции с плавающей запятой (дробные числа)
- Графические операции

### Из чего строятся операционные устройства

- **Регистры** — хранят слова данных
- **Шины** — связывают регистры, передают данные
- **Комбинационные схемы** — выполняют вычисления по управляющим сигналам

### Регистры — подробнее

**Регистр** — это линейка триггеров (ячеек памяти), которые хранят двоичные числа.

Регистры бывают:

1. **Программно-видимые** — те, которые программист может использовать явно (например, AX, BX в Intel)
2. **Косвенно видимые** — «теневые» регистры, которые процессор использует сам
3. **Внутренние специальные** — например, регистр адреса памяти
4. **Внутренние промежуточные** — для временного хранения результатов

### АЛУ — подробнее

**АЛУ** — это комбинационная схема (без памяти внутри), которая:

- Принимает **два операнда** на вход
- Выполняет операцию (сложение, И, ИЛИ и т.д.)
- Выдаёт **результат** на выход

**Принципиальная схема АЛУ включает:**

- Логическое устройство (для операций И, ИЛИ)
- Полный сумматор (для сложения)
- Декодер операции (выбирает, что делать)

Многоразрядное АЛУ строится из нескольких одноразрядных АЛУ, соединённых цепочкой переноса.

## 3. Как операционные устройства связаны с шиной

Типичная фон-неймановская машина:
Регистры (A, B, A+B)
↓ ↓
Входные регистры АЛУ (A, B)
↓ ↓
АЛУ (операция)
↓
Выходной регистр АЛУ (A+B)
↓
обратно в регистры

**Магистральное операционное устройство** — это когда есть:

- **РОН** (регистры общего назначения)
- **Мультиплексоры** (выбирают, откуда взять данные)
- **ОПБ** (операционный блок — то же АЛУ)
- **Магистрали** (шины A, B, C)

### Типы операционных устройств

- **Трёхмагистральные** — три шины (A, B, C)
- **Двухмагистральные** — две шины (A, B)
- **Одномагистральные** — одна шина (A)

## 4. Устройство управления (УУ)

**УУ** — это «начальник», который руководит всем вычислительным процессом.

### Функции УУ

1. Выбрать очередную команду из памяти
2. Расшифровать код операции
3. Сформировать адреса операндов
4. Выбрать операнды из памяти
5. Передать операнды в операционное устройство
6. Запустить выполнение операции
7. Записать результат обратно в память
8. Обработать прерывания

### Микропрограммный автомат

- **Микрооперация** — элементарное действие за один такт.
- **Микрокоманда** — набор микроопераций, выполняемых одновременно.
- **Микропрограмма** — последовательность микрокоманд.

### Два типа УУ

**1. С жёсткой логикой:**

- Схемы соединены раз и навсегда
- Код операции определяет последовательность сигналов
- Счётчик тактов сбрасывается после каждой команды
- Флаги влияют на выработку сигналов

**2. С программируемой логикой:**

- Идею предложил Морис Уилкс в 1951 году
- Есть **память микропрограмм**
- Каждой команде соответствует своя микропрограмма
- Команда интерпретируется в микропрограмму
- В современных процессорах от этого отказались — тормозит производительность

## 5. Процессор Intel 8086

**Intel 8086** — легендарный процессор, родоначальник архитектуры x86.

### Особенности

- **CISC** (Complicated Instruction Set Computer) — усложнённый набор команд
- Всего команд: ~538 (целочисленные, плавающая точка, MMX, XMM)
- Длина команды: от 1 до 15 байт
- Сложные форматы кодирования
- Многокомпонентные способы адресации
- Регистры сильно специализированы

### Регистры 8086

- **AX, BX, CX, DX** — регистры данных
- **SI, DI, SP, BP** — индексные и указательные
- **CS, SS, DS, ES** — сегментные регистры
- **IP** — указатель команды
- **FL** — регистр флагов

### Регистр флагов

| Флаг | Название | Что означает |
|---|---|---|
| CF | Carry Flag | Перенос |
| PF | Parity Flag | Чётность |
| AF | Auxiliary Carry | Вспомогательный перенос |
| ZF | Zero Flag | Ноль |
| SF | Sign Flag | Знак |
| TF | Trap Flag | Отладка |
| IF | Interrupt Enable | Разрешение прерываний |
| DF | Direction Flag | Направление |
| OF | Overflow Flag | Переполнение |

### Сегментная организация памяти

- Память делится на сегменты по 64 КБ
- **Физический адрес** = сегмент × 16 + смещение
- Сегменты: кода (CS), данных (DS), стека (SS), дополнительный (ES)

## 6. Команды и их кодирование

**Команда** — это приказ процессору выполнить операцию.

### Формат команды
[КОП] [Адрес операнда 1] [Адрес операнда 2]

- **КОП** — код операции (что делать)
- **Адреса** — где взять данные

### Архитектуры системы команд

**1. Стековая:**

- Данные хранятся в стеке (LIFO — последним вошёл, первым вышел)
- Операции push (положить) и pop (взять)
- Обратная польская запись: `a b +` вместо `a + b`

**2. Аккумуляторная:**

- Есть один специальный регистр — **аккумулятор**
- Один операнд в аккумуляторе, второй в памяти
- Результат — в аккумулятор
- Короткие команды, но много обращений к памяти

**3. Регистровая:**

- Есть массив регистров общего назначения (РОН)
- Операнды могут быть в регистрах или памяти
- Компактный код, высокая скорость

**4. С выделенным доступом к памяти (Load/Store):**

- Память доступна только через команды load и store
- Все операции — только между регистрами
- Характерна для RISC-архитектур (SPARC, MIPS, Alpha, PowerPC)

### Классификация архитектур
Архитектура системы команд
├── Аккумуляторная
├── Стековая
└── Регистровая
├── CISC (VAX, Intel)
└── RISC (MIPS, SPARC)
└── VLIW (Itanium)

## 7. Рабочий цикл процессора

**Рабочий цикл** — это последовательность действий при выполнении одной команды.

### Этапы рабочего цикла

**1. Выборка команды:**

- Процессор берёт адрес из счётчика команд (СчАК)
- Выставляет его на шину адреса
- Подаёт сигнал чтения (ЧтОП)
- Команда из памяти попадает в регистр команд (РК)

**2. Выборка операндов:**

- Из РК берётся адрес первого операнда
- Выставляется на шину адреса
- Чтение → операнд в аккумулятор (Р1)
- То же для второго операнда → в регистр Р2

**3. Выполнение операции в АЛУ:**

- КОП расшифровывается дешифратором (DC)
- УУиС даёт сигнал АЛУ на выполнение
- АЛУ выполняет операцию
- Результат — в аккумуляторе (Р1)
- АЛУ выставляет сигнал «занято» (Z_АЛУ = 1), потом «свободно» (Z_АЛУ = 0)

**4. Запись результата:**

- Результат из Р1 через порт данных пишется в память
- Адрес — из РК (адрес первого операнда)

**5. Продвижение СчАК:**

- Счётчик команд увеличивается на длину команды
- Теперь он указывает на следующую команду

### Микропрограмма работы процессора
y0, y1, y2, y3, y4, y2, y5, y6, y2, y7, y8, y4, y9, y10

Где:

- y0 — установка СчАК на начальный адрес
- y1 — ПортА := СчАК
- y2 — ЧтОП
- y3 — РК := ПортД
- y4 — ПортА := A1
- y5 — Р1 := ПортД
- y6 — ПортА := A2
- y7 — Р2 := ПортД
- y8 — ПортД := Р1
- y9 — ЗпОП
- y10 — СчАК += L

## 8. Флаги и признаки результата

После выполнения арифметической или логической операции АЛУ формирует **признак результата**:

| Код | Значение |
|---|---|
| 00 | Результат равен нулю |
| 01 | Результат меньше нуля |
| 10 | Результат больше нуля |
| 11 | Переполнение с фиксированной точкой |

**Флаги исключительных ситуаций:**

- Переполнение порядка (для плавающей точки)
- Исчезновение порядка
- Потеря значимости
- Деление на ноль

Эти признаки сохраняются в **регистре признака результата (РПР)** и **регистре флагов (РФ)**.

## 9. Команды перехода

**Команда условного перехода по маске** позволяет организовать ветвление и циклы.

### Формат
[КОП] [Маска] [Адрес перехода]

### Логика работы

- Если маска = 0 → нет операции (NOP)
- Если маска = все единицы → безусловный переход (JMP)
- Если признак результата совпадает с маской → переход по адресу
- Иначе → продолжение последовательного выполнения

## 10. Прерывания

**Прерывание** — это сигнал, который заставляет процессор отвлечься от текущей программы и выполнить другую (обработчик прерывания).

### Типы прерываний

- **Исключения** — возникают внутри процессора (деление на ноль, переполнение)
- **Внешние** — от устройств (клавиатура, таймер, ввод/вывод)

### Аппаратная поддержка

- **Регистр флагов (РФ)** — показывает, какие прерывания возникли
- **Регистр масок (РМ)** — позволяет запретить (замаскировать) некоторые прерывания
- **Указатель стека (УС)** — хранит адрес вершины стека
- **Таблица векторов прерываний (ТВП)** — в первых n словах памяти хранятся команды перехода на обработчики

### Алгоритм обработки прерывания

1. Сохранить СчАК в стек: `ОП[УС] := СК; УС := УС + 1`
2. Загрузить в СчАК адрес вектора: `СК := i`
3. Выполнить команду JMP A_i (переход на обработчик)
4. Выполнить программу обработки прерывания
5. Команда RETI: восстановить СчАК из стека: `УС := УС - 1; СК := ОП[УС]`

### Мультипрограммный режим

- Каждой программе выделяется квант времени (например, 1/30 с)
- По таймеру возникает прерывание
- Процессор переключается на другую программу
- Создаётся иллюзия одновременной работы

## 11. Конфигурируемые процессоры Xtensa

**Xtensa** от Tensilica — это процессоры, которые можно настраивать под конкретную задачу.

**Xenergy** — инструмент, позволяющий:

- Оценить потребление энергии
- Оптимизировать конфигурацию «процессор–память»
- Добавить расширения команд, регистровые файлы
- Снизить общую мощность потребления

## Краткий итог

1. **Процессор** состоит из АЛУ, УУ, регистров, дешифратора, шин.
2. **Операционные устройства** выполняют операции над данными.
3. **УУ** руководит всем процессом, бывает с жёсткой и программируемой логикой.
4. **Intel 8086** — родоначальник x86, CISC-архитектура, сегментная память.
5. **Команды** кодируют операцию и адреса операндов.
6. **Архитектуры команд**: стековая, аккумуляторная, регистровая, Load/Store.
7. **Рабочий цикл**: выборка → выборка операндов → выполнение → запись → продвижение СчАК.
8. **Прерывания** позволяют реагировать на события и переключаться между программами.
9. **Современные процессоры** могут конфигурироваться под задачу (Xtensa).
